## 2. 공부해야 할 핵심 개념 & 로직

### 💡 pnpm의 작동 원리와 Workspace의 이점
* **pnpm의 핵심 원리**: npm은 모든 프로젝트마다 `node_modules`에 동일한 패키지 파일을 중복 복제하여 큰 용량을 소모하지만, pnpm은 전역에 패키지를 딱 한 번 저장한 뒤 **하드 링크(Hard Link)**와 **심볼릭 링크(Symbolic Link)** 방식으로 참조만 시킵니다. 이로 인해 설치 속도가 압도적으로 빠르며 용량을 절약합니다.
* **pnpm workspace**: 루트 `package.json`에서 하위 패키지들을 워크스페이스로 관리하므로, 루트 경로에서 `pnpm dev` 한 줄만 치면 하위 패키지 필터(`--filter`) 기능을 통해 프론트엔드 개발 서버를 즉각 기동할 수 있습니다.

### 💡 2D 드래그 앤 드롭 캔버스의 격자 스냅(Grid Snap) 정렬 수학 공식
배치 캔버스 내에서 요소를 마우스로 자유롭게 끌어다 놓을 때, 삐뚤빼뚤하게 배치되지 않고 바둑판 눈금선에 착착 정렬되도록 하기 위한 **격자 스냅 수학 알고리즘**입니다.

```typescript
// 20px 격자 눈금선 기준의 스냅 공식
const snapToGrid = (val: number): number => {
  return Math.round(val / 20) * 20;
};
```
1. `val / 20`을 통해 해당 좌표가 20px 그리드 중 몇 번째 칸에 가까운지 비율을 구합니다.
2. `Math.round()`로 반올림하여 가장 근접한 눈금 칸 수(정수)를 결정합니다.
3. 다시 `* 20`을 하여 진짜 정렬되어야 할 최종 px 좌표값으로 복원시킵니다.

### 💡 React 커스텀 훅(Custom Hook)을 이용한 관심사 분리(SoC)
대시보드 컴포넌트 파일 하나에 타이머 째깍거림, 버튼 클릭 시의 모달 제어, 서버 상태 fetch, 비즈니스 에러 롤백 등 모든 코드가 모여 있으면 파일 길이가 수천 줄로 늘어나 가독성이 엉망이 됩니다.
비즈니스 로직 부분만 `useDashboard.ts`라는 별도 커스텀 훅 파일로 격리하여 묶어두고, 뷰 컴포넌트는 오직 이 훅에서 반환받은 데이터와 제어 함수를 렌더링에 매핑하는 역할에만 집중하게 하는 기법입니다.

## 3. 핵심 트러블슈팅
* **`verbatimModuleSyntax` 컴파일 에러**: TypeScript 5버전 컴파일 옵션에 맞춰 타입 선언부를 임포트할 때는 반드시 `import type { ReactNode }`처럼 `type` 키워드를 명시하여 소거되도록 수정하여 해결했습니다.
* **as const 리터럴 단언 및 타입 유추 에러**: 객체가 읽기 전용으로 타입 유추되어 동적 할당 과정에서 오류를 뱉는 문제를 변수 선언 시 명시적으로 `string` 타입을 할당해주어 정적 컴파일러를 만족시켰습니다.

## 2. 공부해야 할 핵심 개념 & 로직

### 💡 ORM (Object-Relational Mapping)과 JPA
전통적인 백엔드 개발에서는 DB 테이블 정보를 바탕으로 쿼리문(`SELECT * FROM users ...`)을 손수 짜서 쏴주어야 했습니다. 이 방식은 테이블 필드가 하나만 늘어나도 관련 SQL 쿼리문 수십 개를 일일이 찾아 고쳐야 해서 유지보수가 매우 고통스럽습니다.
**ORM**은 자바의 **객체(Object)**와 데이터베이스의 **테이블(Relation)**을 어노테이션으로 매핑해주는 기술입니다.
* **JPA**: 자바 ORM 기술의 표준 명세(인터페이스)입니다.
* **JPA의 동작 원리**: 우리가 `userRepository.save(user)`라는 자바 친화적인 메서드를 한 줄 호출하면, JPA 구현체인 Hibernate가 자바 객체를 스스로 분석하여 알맞은 SQL 쿼리(`INSERT INTO users ...`)를 백그라운드에서 실시간으로 자동 작성해 전송해 줍니다.

### 💡 JPA 핵심 어노테이션 정리
* **`@Entity`**: 이 클래스는 그냥 일반 자바 클래스가 아니라 데이터베이스의 테이블과 1:1로 매핑되는 특별한 객체임을 스프링(JPA)에 선언합니다.
* **`@Table(name = "users")`**: 실제 DB의 테이블 이름을 지정합니다. 데이터베이스에 따라 `user` 같은 단어가 시스템 예약어와 충돌하는 경우가 있으므로, 명시적으로 복수형 테이블 이름(`users`)을 부여해 충돌을 방지합니다.
* **`@Id` & `@GeneratedValue(strategy = GenerationType.IDENTITY)`**: DB 테이블의 고유 식별자인 기본키(PK)를 매핑합니다. `IDENTITY` 전략을 사용하면 MySQL의 `AUTO_INCREMENT` 속성을 사용해 값이 1, 2, 3... 순서로 자동 생성 및 저장되도록 보장합니다.
* **`@Enumerated(EnumType.STRING)`**: 자바의 Enum(열거형) 값을 데이터베이스에 저장할 때 반드시 사용해야 하는 필수 옵션입니다.
  * `EnumType.ORDINAL`(기본값): DB에 enum 순서 번호(0, 1, 2)로 저장됩니다. 만약 나중에 enum 중간에 새로운 값을 끼워 넣으면 번호 순서가 완전히 꼬여 데이터 대참사가 발생합니다.
  * `EnumType.STRING`: 안전하게 문자열("ROLE_CUSTOMER") 그대로 저장하므로 유지보수에 매우 안전합니다.

### 💡 `@ManyToOne(fetch = FetchType.LAZY)`의 지연 로딩 원리
매장(`Store`) 엔티티는 사장님(`User`)에 종속되는 다대일 관계입니다.

```java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User owner;
```

* **즉시 로딩 (`FetchType.EAGER`)**: 매장 상세 정보만 가져오고 싶어서 `Store`를 가져올 때, JPA가 사장님의 회원 가입 정보까지 SQL 조인(JOIN)을 걸어 한꺼번에 즉시 다 긁어옵니다. 매장 100개를 리스트업하면 사장님 100명 조회 쿼리가 추가로 나가는 심각한 성능 저하(N+1 문제)가 일어납니다.
* **지연 로딩 (`FetchType.LAZY` - 권장)**: 매장 정보만 우선 조용히 가져오고, 사장님 정보는 조회하지 않고 비워둡니다(가짜 프록시 객체 대입). 이후 자바 코드 상에서 `store.getOwner().getName()`처럼 **실제 사장님 객체의 알맹이가 필요한 그 시점에 비로소 사장님 정보 조회를 위한 SQL을 추가로 날립니다.** 실무 성능 최적화의 제1 원칙입니다.

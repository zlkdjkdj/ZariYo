# [ZariYo 개발 & 학습 노트] 2026-07-07

## 1. 오늘의 작업 내용
* **Vite 프론트엔드 프로젝트 생성**: React + TypeScript 템플릿으로 프로젝트 기본 뼈대를 스캐폴딩했습니다.
* **스타일링 환경 구축**: Tailwind CSS v4 및 Pretendard 폰트를 연동하여 디자인 유연성을 확보했습니다.
* **컴포넌트 단위 리팩토링 및 모듈화**: `Header`, `Hero`, `Features`, `Architecture`, `Footer`, `LandingPage` 형태로 분할하여 코드 결합도를 낮추었습니다.

## 2. 공부해야 할 핵심 개념 & 로직

### 💡 React + Vite의 빠른 핫 리로딩(HMR) 원리
Vite는 기존 Webpack 방식과 달리, 브라우저에서 지원하는 **Native ES Modules (ESM)**를 활용합니다. 
* **Webpack**: 소스코드가 조금만 수정되어도 프로젝트 전체를 다시 빌드(Bundle)하여 브라우저에 전달하므로 프로젝트가 커질수록 느려집니다.
* **Vite**: 소스코드를 수정하면 브라우저가 필요한 파일만 HTTP 요청을 통해 동적으로 가져가므로, 프로젝트 크기에 상관없이 수정 사항이 **0.1초 만에 즉각 화면에 반영**됩니다.

### 💡 백엔드와 프론트엔드 디렉토리 분리(이원화)의 가치
하나의 폴더에 프론트엔드와 백엔드가 섞여 있으면 다음과 같은 문제가 발생합니다:
1. 빌드 도구와 버전(Node.js vs JDK) 관리의 꼬임 현상.
2. 깃 커밋 로그의 혼재로 인한 협업 능률 저하.
3. 배포(Deployment) 시 불필요하게 프론트/백 코드가 같이 패키징되는 문제.
따라서 `ZariYo-FrontEnd`와 `ZariYo-BackEnd`로 격리하여 각자 독립적인 빌드 및 무결성을 유지할 수 있도록 설계했습니다.

### 💡 Docker Compose의 가상화 인프라의 강점
로컬 컴퓨터에 직접 MySQL 데이터베이스나 Redis 메모리 서버를 설치하려면 OS에 맞춰 설정 파일을 손수 만져야 하고, 설치 버전이 꼬이면 지우기도 매우 까다롭습니다.
**Docker Compose**를 사용하면 미리 정의된 스키마 이미지(`mysql:8.0`, `redis:7.2`)를 가져와 격리된 가상 컨테이너 위에 실행하므로 명령 한 줄(`docker-compose up -d`)로 완벽히 동일한 환경을 1초 만에 구성할 수 있습니다.

## 3. 핵심 트러블슈팅
* **TypeScript 미사용 임포트 변수 에러**: `tsconfig.json`의 Strict 린트 옵션에 의해 쓰이지 않는 변수가 선언되면 빌드가 막힙니다. 불필요한 임포트 구문을 제거하여 해결했습니다.
* **폴더 이전 후 IDE 캐시 에러**: 파일을 하위 폴더로 이동시켰음에도 에디터가 예전 경로의 캐시 데이터를 들고 있어서 컴파일 에러를 표시했습니다. 열린 파일 버퍼를 비우고 TS Server를 재기동하여 캐시를 동기화했습니다.
